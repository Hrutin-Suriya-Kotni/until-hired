# Consolidated review: until-hired 1.0 design

Target: `docs/design/until-hired-1.0.md` (first draft, 172 lines).
Method: [Elephant Goldfish Model](https://egm.dev/). The author (the "Elephant", full context) wrote the draft. Nine reviewers with fresh context (the "Goldfish") read it independently and did not see each other's work.

| Reviewer | Focus | Blockers | Majors | Nits |
|---|---|---|---|---|
| Comprehension | Can a newcomer follow it? | 0 | 4 | 6 |
| Structural critic | Sections, order, missing tables | 0 | 5 | 4 |
| Design critic | Soundness of each decision | 1 | 6 | 3 |
| Style critic | Plain language, jargon, length | 0 | 2 | 9 |
| Zoom-out | Is this the simplest design that works? | 1 | 9 | 7 |
| Inventive catalyst | False compromises | 0 (advisory mode) | 10 | 2 |
| Implementation readiness | Can it be built without new decisions? | 1 | 15 | 4 |
| Codebase details | Does the plan match the code? | 3 | 14 | 3 |
| Security and privacy | Threats, data flows, enforcement | 3 | 13 | 2 |

After removing duplicates, there are **9 distinct blockers and 25 distinct majors**. Each is listed below with the decision taken.

- **FIX** means the change was made.
- **CONTEST** means it was not, and the reason is given.
- **LATER** means it is recorded in `ROADMAP.md` and is not needed for 1.0.

## Blockers

| # | Finding | Raised by | Decision |
|---|---|---|---|
| B1 | **Untrusted text still reaches the shell.** `check`, `list --company` and `claimable` had no file input. Several skills (apply-assist, offer-coach, application-kit, growth-engine, candidate-intake) and the ntfy `curl` example put copied page text into command lines. The fix was a hand-kept list, and it already had gaps. | Zoom-out, Inventive, Readiness, Codebase, Security, Design | **FIX, made structural.** (1) `--json FILE` is built once into the shared argument parser, so every command of every tool accepts it automatically. Keys use the option name with underscores. JSON values are passed to argparse as `--key=value`, so a value that starts with `-` cannot become an option. (2) Notifications go through `notify.py --json`, with no `curl`. (3) A lint in `tests/test_package.py` fails the build when any skill, agent or reference file shows a tool command with a free-text option or a quoted placeholder. (4) On Claude Code, a PreToolUse hook shipped with the plugin blocks calls to the tools that use free-text options, `$(…)`, backticks or heredocs, before the shell runs them. On Antigravity and Codex this rule is still instructions plus lint, and the control table in the design doc says so. |
| B2 | **`--json` clashed with required options**, and "ids may be options" contradicted "no mixing". | Readiness, Codebase, Zoom-out | **FIX.** JSON keys are merged into argv before parsing, so `required=True` keeps working. Typed options (`--id`, `--status`, `--dir`) may sit next to `--json`. Exit 2 only when the same key appears in both places. |
| B3 | **knowledge.py did not write atomically.** graph.json and market.json were written one after the other with `write_text`. tracker.py's dashboard had the same problem. | Codebase, Zoom-out, Inventive, Security | **FIX.** Every write in every tool now goes through one `atomic_write`: a temporary file, fsync, then `os.replace`, with the previous copy kept as `.bak`. If a file cannot be parsed, the tool stops with exit 1 and names the `.bak`. It never resets data on its own. |
| B4 | **A hostile job form can collect personal data.** In `prepare` mode the agent fills every field before it stops, and the page's script can read each value as it is typed. Nothing limited which sites receive ANSWERS.md values. | Security | **FIX.** (1) ANSWERS.md is split into *Basic* answers (name, email, phone, links) and *Sensitive* answers (date of birth, pay, visa, notice terms, diversity, background). (2) `tracker.py disclose` checks the form's host against a built-in list of known hiring-system hosts plus the candidate's own `apply.allowed_hosts`. It records which fields (never their values) were given to which host, and exits 6 when the host is not allowed. (3) On a host that is not allowed, the agent may only gather information (`discover`); it does not type into the form. (4) Sensitive answers need a yes from the candidate for each job, unless the candidate has turned on `apply.sensitive_on_known_hosts`. (5) README no longer says answers "never leave the form". (6) A new scenario tests a fake Google Form. Enforcement is instructions plus an audit log, and the control table says so. |
| B5 | **inbox-sync told the agent to pass emailed verification codes to the form-filling agent.** That is an account-takeover path. | Security | **FIX.** Codes are never read out, copied or passed between agents. The agent tells the candidate that a code arrived. A lint test fails if any skill or agent file tells the agent to use a code. A new scenario covers this. |
| B6 | **The JSON hand-off file raced.** Parallel scouts could both write `job-1.json`. Relative paths broke, the files were never deleted, and `--json -` (stdin) invited `echo` or a heredoc. | Zoom-out, Inventive, Readiness, Codebase, Security | **FIX.** `tracker.py new-input --agent scout` creates a unique, empty `<ws>/.inbox/<agent>-<time>-<random>.json` (mode 600) and prints its absolute path. The agent fills the file with its own file-writing tool. Any command that reads an input file from `.inbox/` deletes it after exit 0, 3 or 4. Stdin input is removed. `.inbox/` is git-ignored. |
| B7 | **Racy stale-lock takeover.** Two waiters could both decide a lock was stale and both write. The stale age (60 s) was also longer than the wait (10 s). | Zoom-out, Inventive, Readiness, Codebase, Security | **FIX, by replacing the design.** The lock is now an operating-system lock (`fcntl.flock` on macOS and Linux, `msvcrt.locking` on Windows) held on `<ws>/.lock`. The system releases it when the process exits, even after a crash, so there is no stale logic and no takeover. Waiters give up after 20 s with exit 5. tracker and knowledge share one lock per workspace. |
| B8 | **The personal-data test would publish the author's data.** It had to contain the phone number and sheet id it searched for. | Readiness, Zoom-out, Codebase, Security | **FIX.** The test uses generic patterns only: phone-number shapes, the 44-character Google Sheets id, email addresses outside `example.com`, and Indian PAN and Aadhaar shapes, with a short allowlist. No author data is in the repository. The git history was scanned before the first push. |
| B9 | **The headline security test could never fail.** tracker.py never starts a shell, so `"; touch /tmp/pwned"` proved nothing, and `/tmp` does not exist on Windows. | Security, Inventive, Codebase | **FIX.** It is replaced by (a) the skill-text lint, (b) unit tests of the guard hook with real injection strings, and (c) the injection scenarios in `evals/`. A temporary-folder sentinel is kept as a regression test of the tools themselves. |

## Majors

| # | Finding | Decision |
|---|---|---|
| M1 | Spreadsheet safety changed the stored data permanently. The agent saw `'=…`, and the Google Sheets mirror was not covered. | **FIX.** Reversible encoding: any cell that starts with `= + - @ \t \r '` gets one `'` added on write, and that `'` is removed on read. A value that really starts with `'` round-trips exactly. Every cell is encoded, whether or not it was validated. `tracker.py export --format json` produces mirror-safe values, and the skill tells the agent to write with RAW input. |
| M2 | Silent truncation dropped new notes once a job's notes reached the limit. | **FIX.** A single input value over its limit is rejected with exit 2, not cut. Only accumulated notes and evidence are capped, at 30,000 characters (under the 32,767-character spreadsheet cell limit). They keep the newest text and print a warning. |
| M3 | Field rules were incomplete (`next_action`, `round` and `with_whom` broke DASHBOARD.md). Only `\x00` was stripped. | **FIX.** One shared sanitiser: NFC normalisation; it removes C0/C1 controls, DEL, bidirectional overrides, zero-width characters and the byte-order mark; it turns newlines into ` / `, so every stored field is one line. Every generated Markdown file escapes `\ \| [ ] ( ) ! < > \` * _`. JSON values must be strings, numbers, booleans or (for list fields) arrays of strings. Input files are capped at 256 KB, and `jd` at 100 skills. |
| M4 | Excel use could wipe the tracker: a byte-order mark blanked every id, `;` separators made one column, a file held open broke `os.replace`, and Excel saves raced with the agent. | **FIX.** Files are read as `utf-8-sig`. Before every write the header is checked: if it is not exactly as expected, the tool writes nothing, explains what is wrong and exits 1. If a file changed while the command was running, the tool exits 5. `os.replace` retries for 5 s on PermissionError, then exits 5 with "close it in your spreadsheet app". There is a `.bak` before every replace. |
| M5 | The consent gates (`submit` mode, skill level `evidenced`) live in files the agent can edit. | **Partly CONTEST.** An agent with a shell can edit any file, including the tools themselves, so no file-based gate can bind it. What was done instead: (1) on Claude Code the guard hook asks the candidate before any edit to `config.json`, `profile/ANSWERS.md`, `FACTS.md`, `DO_NOT_CLAIM.md` or `bin/`; (2) `knowledge.py` logs every level change, `setup_workspace.py --check` reports platforms in `submit` mode and when that was turned on, and the weekly review lists both; (3) the control table states the limit plainly. |
| M6 | Path traversal: material folders were built from company names, e.g. `../../.claude/agents`. | **FIX.** `tracker.py add` returns `folder: materials/<id>-<slug>`. The slug is `[a-z0-9-]{1,48}` and Windows reserved names are refused. `tracker.py folder --id N` prints it again. Skills use only that folder. Tests cover `../`, absolute paths, `CON` and Unicode dots. |
| M7 | Injected text was saved and read again in later sessions (LEARNINGS.md, jd.md, research.md). | **FIX.** Subagent lessons go to `knowledge/LEARNINGS.pending.md`. Only the candidate's OK moves them into LEARNINGS.md, which every session trusts. Files of copied page text start with an `UNTRUSTED CONTENT` banner. A scenario tests that a lesson planted in one session has no effect in the next. |
| M8 | No data inventory. Only two files were protected. | **FIX.** The design doc and SAFETY.md now have a data table: each class, its files, who receives it (model provider, ntfy, mirrors, job sites) and where it must never go. The default `.gitignore` excludes `profile/`, `materials/`, `tracker/contacts.csv`, `knowledge/reviews/`, `.inbox/` and `config.local.json`; tracking any of them is an explicit opt-in. `mirror_id` and `inbox.address` moved to `config.local.json`. `--check` warns about iCloud, Dropbox, OneDrive and Google Drive folders, and about a git repository with a remote that tracks sensitive files. There are wipe instructions. |
| M9 | Notifications revealed the job search on lock screens, and the topic travelled through command lines. | **FIX.** By default messages carry counts only ("until-hired: 2 items need you"); company names are an opt-in. `notify.py` reads the topic itself and sends it in the JSON body, never on a command line. `--check` warns when the topic is shorter than 20 characters or appears in a known hook file. |
| M10 | Subagents that read hostile pages inherit every tool. | **Partly CONTEST.** A `tools:` list in agent frontmatter is not portable: Antigravity can refuse to start an agent whose list names tools it does not have. The guard hook instead enforces the dangerous parts (tool calls, protected files) on Claude Code. `references/permissions.md` gives recommended allow, ask and deny rules for each harness. |
| M11 | doctor.py in `bin/` could not see the skill, and its checks would copy constants that drift. | **FIX (zoom-out proposal).** There is no doctor.py. `setup_workspace.py --check` is a read-only report that runs from the skill: it compares tool hashes, config keys against the template, CSV headers imported from the tracker, file modes, `.gitignore`, sync folders, git remote, topic strength and an ANSWERS-leak scan. Re-running `setup_workspace.py` without `--check` performs the safe repairs (refresh tools, migrate secrets, fix modes, add `.gitignore` lines). |
| M12 | "One version number" in fact lived in about 20 places. | **FIX.** The single source is root `plugin.json`. The other manifests and `uhlib.__version__` must match, and `test_package` checks them. `metadata.version` was removed from the SKILL.md files. |
| M13 | Existing 0.1.0 workspaces had no upgrade path; `ntfy_topic` in config.json would fail the new check. | **FIX.** Setup migrates it: secret values move into `config.local.json` (mode 600), config.json keeps a backup, and existing CSVs are checked and normalised. |
| M14 | Phase 1 broke CI. Manifests were described as "rewrite" but did not exist. There was no file list. | **FIX.** The revised doc has one file table (create, modify, delete, move) used as the write allowlist. CI paths change in the same commit as the move. |
| M15 | Manifests were not tested, and Codex was promised but untested. | **FIX + label.** Offline manifest tests (sources resolve, paths exist, shared fields equal). `install.py` runs in CI on three operating systems. Codex is labelled *experimental* in the README. |
| M16 | Supply chain: users run whatever is on the default branch, CI tokens may default to write, `install.py` deleted folders without asking. | **FIX.** CI has `permissions: contents: read` and `persist-credentials: false`, every action is pinned by commit SHA, and Dependabot covers actions. `install.py` refuses to replace a folder without its own marker file unless given `--force`. README documents installing a release tag. Branch protection, signed tags, secret scanning and private vulnerability reporting are repository settings, so they are on the owner's release checklist (they cannot be set from code). |
| M17 | Security claims did not say how they are enforced; SAFETY.md said the tools make "no network access". | **FIX.** The design doc has a control table (control / enforced by code, test, harness hook or instructions only). SAFETY.md now says: one tool, notify.py, makes network calls, only to the configured ntfy server. |
| M18 | One live run on one harness is thin evidence for behaviour that varies from run to run. | **FIX within limits.** Scenarios grew from 22 to 28. A deterministic checker (`setup_workspace.py --check --invariants`) checks the workspace after any session: evidence on every applied-or-later job, duplicates, no Sensitive ANSWERS value outside `profile/`, blocked disclosures. ("Nothing submitted outside submit mode" needs the mode recorded per submission; see the drift report.) The live run uses it. **LATER:** five runs per harness as a release gate. |
| M19 | "Ingest" pull model for readers (inventive). | **LATER.** The unique `.inbox` names, deletion and lock already close the race; ingest is a larger change. |
| M20 | Records of external edits in the event log (inventive). | **LATER.** For 1.0, changes made while a command runs are caught and stop the command (M4). |
| M21 | `/dev/tty` confirmation for submit mode (security). | **CONTEST.** Some harnesses run commands in a pseudo-terminal that the agent can type into, so this gives false assurance. M5 covers it instead. |
| M22 | Shared helper module versus copies in each tool. | **FIX.** One `uhlib.py` is copied with the tools. Each tool adds its own folder to `sys.path`, so it also works under `python -I`. |
| M23 | The smoke test duplicates the unit tests. | **FIX.** The smoke test becomes the unittest baseline. New tests cover only new behaviour. |
| M24 | Three copies of the PR checklist; SAFETY.md and SECURITY.md disagreed on how to report. | **FIX.** One checklist in CONTRIBUTING.md, which the PR template links to. SAFETY.md points to SECURITY.md for vulnerabilities. |
| M25 | Design doc structure and style: altitude drops, jargon ("EGM", "Elephant"), missing metadata, baseline, threat model, alternatives per goal, exit-code table. | **FIX.** The doc was rewritten as v2. |

## Nits
All nits are fixed or covered by the decisions above. The main ones:
- `os.umask(0o077)` at tool start.
- chmod only on folders setup created.
- Exit-code table extended (6 = limit or host not allowed).
- `valid_date` accepts `""` to clear a date.
- The workflow `test.yml` is replaced, and the doc says so.
- CHANGELOG no longer calls 0.1.0 a public release.
- Antigravity's root `plugin.json` is named "the Antigravity manifest".

## Traceability
Each blocker and major above maps to:
- a section of `until-hired-1.0.md` v2 (§ numbers in its control table);
- at least one test in `tests/` or scenario in `evals/scenarios.md`.

`docs/design/reviews/drift_report.md` records where the built code differs from the design.
